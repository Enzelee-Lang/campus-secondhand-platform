## 1. 系统概述

**校园二手物品交易系统** 是一个面向高校学生的 C2C 二手交易后端服务，提供用户注册/登录、商品发布与检索、分类浏览、评价互信、收藏、站内消息、违规举报、后台管理等能力。

| 项目 | 内容 |
|---|---|
| 服务名称 | campus-backend |
| 端口 | **8080** |
| 数据库 | `campus_second_hand`（8 张表） |
| 框架 | Spring Boot 3.4.5 |
| 持久层 | Spring Data JPA（Hibernate） |
| 数据库驱动 | MySQL Connector/J 9.x |
| 接口文档 | springdoc-openapi 2.7.0（Swagger UI） |
| Java | 17 |
| 构建 | Maven（工程自带 mvnw） |

## 2. 总体架构与模块划分

### 2.1 分层架构

本项目采用 **单体分层** 结构，标准调用链为：

```
Controller(接口层) → Repository(JPA 数据访问层) → MySQL 数据库
        └─ 统一经 Result 包装返回 JSON
```

> 说明：为课程作业演示的简洁性，本工程未单独抽取 Service 层（老师演示视频中的项目同样存在此简化风格）。
> 业务规则（唯一性校验、状态修改、MD5 加密等）直接写在 Controller 内；数据访问统一委托给 Repository 的 JPA 派生方法或 @Query 查询。
> 若后续需要接入复杂业务，可将 Controller 中的逻辑下沉到 `service/` 包，接口签名无需变动。

### 3.3 实体设计要点（映射关系）

- **`Item`**：`@PrePersist` 填充 create_time/update_time，`@PreUpdate` 维护 update_time —— 解决 `create_time NOT NULL` 约束下 JPA 插入空值的问题。
- **`Favorite`**：`@IdClass(FavoriteId.class)` 复合主键映射，`FavoriteId` 为可序列化的独立主键类。
- **`User` / `Admin`**：密码字段用 `@JsonProperty(access = WRITE_ONLY)`（见第 4 章），保证密码只进不出。
- 各实体 ID 均采用 `@GeneratedValue(strategy = GenerationType.IDENTITY)` 自增。

## 4. 通用机制

### 4.1 统一响应包装 Result<T>

`common/Result.java` —— 所有接口返回统一结构：

```json
{ "code": 200, "message": "success", "data": { ... } }
```

| code | 含义 |
|---|---|
| 200 | 成功 |
| 404 | 资源不存在（用户/商品/评价/消息/举报等查无） |
| 500 | 业务失败（用户名已存在、密码错误、重复收藏等，message 携带原因） |

静态工厂：`Result.ok(data)` / `Result.ok()` / `Result.error("msg")` / `Result.error(code,"msg")`。

### 4.2 MD5 密码加密

`util/Md5Util.java`：

```java
public static String md5(String text)   // MessageDigest MD5 → 32 位小写十六进制
```

- 注册/创建账号时：`password = Md5Util.md5(明文)` 后落库。
- 登录时：将入参密码 MD5 后与库中密文比对，**明文不落库、不传输比对**。
- 响应序列化安全：实体密码字段声明 `@JsonProperty(access = JsonProperty.Access.WRITE_ONLY)`，**任何查询结果都不会把 password 返回给前端**（该方案替代失效的 `@JsonIgnore` + Lombok 组合）。

### 4.3 全局跨域

`config/CorsConfig.java` 对 `/**` 放行任意 Origin，允许 GET/POST/PUT/DELETE/OPTIONS，方便前端/小程序联调（浏览器跨域直接可调）。

### 4.4 游标分页（CursorPageVo + /api/items/page）

大数据量下优于传统 offset 翻页：不随页码变深而变慢、翻页过程中新增数据不产生重复/遗漏。

```java
// CursorPageVo<T>：entityList / hasNextPage / nextCursor / pageSize
// 排序键 = create_time（ISO-8601，如 2026-09-02T20:28:21）
// Repository @Query：WHERE (:cursor IS NULL OR i.createTime < :cursor)
//                     ORDER BY i.createTime DESC
```

调用方每页多取 1 条（pageSize+1）判断 `hasNextPage`，并把当页最后一条的 create_time 作为下一页 `nextCursor` 回传。

### 4.5 CSV 导出（/api/items/export）

仿参考项目中的"文件导出"能力：设置 `Content-Disposition: attachment` 响应头触发浏览器下载；先写 UTF-8 BOM（`\ufeff`）保证 Excel 直接打开中文不乱码；含逗号/引号/换行的字段按 CSV 规范双引号包裹转义；成色数字映射为中文后输出。

## 5. 模块一 认证模块（/api/auth）

**控制器**：`AuthController`　**数据访问**：`UserRepository`、`AdminRepository`　**表**：t_user、t_admin

### 接口清单

| 方法 | 路径 | 入参 | 返回 data | 说明 |
|---|---|---|---|---|
| POST | /api/auth/register | RegisterRequest{username,password,email,phone,studentId,schoolName} | User | 用户注册 |
| POST | /api/auth/login | LoginRequest{username,password,type} | Map{type, user 或 admin} | 登录（type=user/admin 分流） |

### 实现逻辑

**注册**：
1. `existsByUsername` 校验用户名是否已被占用 → 占用返回 500"用户名已存在"。
2. `existsByStudentId` 校验学号是否已被注册 → 占用返回 500"学号已被注册"。
3. 密码经 `Md5Util.md5()` 加密，`status=1`，`save` 落库。

**登录**：
1. 入参密码 MD5。
2. `type=admin` → 走 t_admin：查 `findByUsername`；比对密文 → 失败返回"管理员账号或密码错误"；`status==0` 返回"该管理员已被禁用"。
3. `type=user`（默认）→ 走 t_user：查 `findByUsername` 比对密文 → 失败返回"用户名或密码错误"；`status==0` 返回"该账号已被禁用"。
4. 成功将 `type` 与实体对象放入 Map 返回（**响应中不含密码**，见 4.2）。

## 6. 模块二 用户模块（/api/users）

**控制器**：`UserController`　**数据访问**：`UserRepository`　**表**：t_user

### 接口清单

| 方法 | 路径 | 入参 | 返回 data | 说明 |
|---|---|---|---|---|
| GET | /api/users | — | List\<User\> | 用户列表（按 create_time 倒序） |
| GET | /api/users/{id} | 路径 id | User | 用户详情 |
| GET | /api/users/student/{studentId} | 路径 studentId | User | 按学号查询 |
| PUT | /api/users/{id} | 路径 id + User 部分字段 | User | 修改个人资料 |

### 实现逻辑

- **列表/详情/按学号**：直接调用 `findAll(Sort.by(DESC,"createTime"))` / `findById` / `findByStudentId`（JPA 派生查询），查无返回 `Result.error(404,"用户不存在")`。
- **修改资料**（`findById` 取实体后**局部更新**）：仅对 patch 中**非 null 字段**逐个 set（email/phone/avatar/schoolName），再 `save` 整体持久化 —— 空字段不覆盖，天然支持"只改想改的项"。该接口不开放改 username/studentId/status（身份与状态字段受控）。

## 7. 模块三 商品模块（/api/items）

**控制器**：`ItemController`　**数据访问**：`ItemRepository`　**表**：t_item

### 接口清单

| 方法 | 路径 | 入参 | 返回 data | 说明 |
|---|---|---|---|---|
| GET | /api/items | ?categoryId=?&keyword=? | List\<Item\> | 全量商品（兼容旧端，支持分类/关键字过滤） |
| GET | /api/items/page | ?cursor=&pageSize=&categoryId=&keyword= | CursorPageVo\<Item\> | **游标分页**（首推新端使用） |
| GET | /api/items/{id} | 路径 id | Item | 商品详情（浏览量+1） |
| GET | /api/items/user/{userId} | 路径 userId | List\<Item\> | 某人发布的商品 |
| GET | /api/items/export | ?categoryId= | CSV 文件流 | **导出 CSV**（见 4.5） |
| POST | /api/items | Item JSON | Item | 发布商品（强制 status=1） |
| PUT | /api/items/{id} | 路径 id + Item 部分字段 | Item | 修改商品 |
| DELETE | /api/items/{id} | 路径 id | Void | 删除商品 |

### 实现逻辑

- **全量列表**：`findAll(DESC by createTime)` 后按需内存过滤 —— categoryId 精确匹配、keyword 对 title **忽略大小写包含**匹配。
- **游标分页**（`/page`，新能力）：
  1. 解析 cursor（ISO-8601，非法/为空视为首页，容错不 500）。
  2. 按过滤条件分派到 3 个 `@Query` 方法之一（全量 / 按分类 / 按关键字），三者统一 `createTime < cursor ORDER BY createTime DESC` 语义。
  3. 每页取 `pageSize+1` 条 → 多出 1 条说明有下一页（`hasNext=true`），截断为 pageSize 返回；`nextCursor = 当页末条 create_time`。pageSize 默认 10、上限 100。
- **详情**：`findById` 命中后 `viewCount+1` 再 save（浏览量统计），未命中 404。
- **发布**：无视前端传的 status，强制置 1（新发布默认在售）。
- **修改**：findById 局部更新（title/description/price/originalPrice/conditionLevel/images/categoryId/status 任一非 null 即覆盖）。
- **导出**：可选按 categoryId 过滤，写表头（商品ID,标题,描述,售价,原价,成色,状态,浏览量,发布时间）+ BOM + CSV 转义，stream 输出（见 4.5）。
- **删除**：`deleteById`，返回 200。

## 9. 模块五 评价模块（/api/reviews）

**控制器**：`ReviewController`　**数据访问**：`ReviewRepository`　**表**：t_review

### 接口清单

| 方法 | 路径 | 入参 | 返回 data | 说明 |
|---|---|---|---|---|
| GET | /api/reviews/target/{userId} | 路径 userId | List\<Review\> | 某用户（卖家）收到的评价 |
| GET | /api/reviews/item/{itemId} | 路径 itemId | List\<Review\> | 某商品的全部评价 |
| POST | /api/reviews | Review JSON | Review | 发表评价（rating 1-5） |

- 回复：`findById` 命中后 set reply 再 save，未命中 404 —— 完成"买家评价 → 卖家回评"闭环。

## 10. 模块六 收藏模块（/api/favorites）

**控制器**：`FavoriteController`　**数据访问**：`FavoriteRepository`　**表**：t_favorite

### 接口清单

| 方法 | 路径 | 入参 | 返回 data | 说明 |
|---|---|---|---|---|
| GET | /api/favorites/user/{userId} | 路径 userId | List\<Favorite\> | 某用户的收藏列表 |
| POST | /api/favorites | Favorite JSON{userId,itemId} | Favorite | 添加收藏 |
| DELETE | /api/favorites/{userId}/{itemId} | 路径双 id | Void | 取消收藏 |

### 实现逻辑

- **联合主键**：t_favorite 以 (user_id, item_id) 为 PK，实体用 `@IdClass` 映射，同一用户+商品在库中唯一。
- **添加去重**：先 `existsByUserIdAndItemId` 校验，已收藏返回 500"已收藏该商品"，否则 save。
- **取消**：`deleteByUserIdAndItemId(userId, itemId)` 精确删除（Repository 派生删除方法）。

## 11. 模块七 消息模块（/api/messages）

**控制器**：`MessageController`　**数据访问**：`MessageRepository`　**表**：t_message

### 接口清单

| 方法 | 路径 | 入参 | 返回 data | 说明 |
|---|---|---|---|---|
| POST | /api/messages | Message JSON | Message | 发送站内消息 |
| GET | /api/messages/inbox/{userId} | 路径 userId | List\<Message\> | 收件箱 |
| GET | /api/messages/outbox/{userId} | 路径 userId | List\<Message\> | 发件箱 |
| GET | /api/messages/unread/{userId} | 路径 userId | Long | 未读数 |
| PUT | /api/messages/{id}/read | 路径 id | Message | 标记已读 |

### 实现逻辑

- **发送**：强制 `isRead=0` 后 save（新消息默认未读；msgType 默认 1 私聊）。
- **收/发件箱**：`findByReceiverId` / `findBySenderId` 派生查询。
- **未读数**：`findByReceiverIdAndIsRead(userId, 0)` 查出后 stream 计数（数据量小，内存计数即可）。
- **标已读**：`findById` 命中 → set `isRead=1` → save；未命中 404。

## 12. 模块八 举报模块（/api/reports）

**控制器**：`ReportController`　**数据访问**：`ReportRepository`　**表**：t_report

### 接口清单

| 方法 | 路径 | 入参 | 返回 data | 说明 |
|---|---|---|---|---|
| POST | /api/reports | Report JSON | Report | 用户提交举报 |
| GET | /api/reports | ?status=0/1/2（可空） | List\<Report\> | 举报列表（管理端，可按状态筛） |
| PUT | /api/reports/{id}/handle | 路径 id + ?status= | Report | 处理举报（通过/驳回） |

### 实现逻辑

- **提交**：强制 `status=0`（待处理）落库 —— 举报默认进入待审队列。
- **列表**：status 为空查全部 `findAll()`，否则 `findByStatus(status)` 过滤。
- **处理**：`findById` 命中后按入参 status（1 已处理 / 2 已驳回）更新 —— 管理端"处理-闭环"。

## 13. 模块九 管理端模块（/api/admin）

**控制器**：`AdminController`　**数据访问**：`UserRepository`、`ItemRepository`、`AdminRepository`、`ReportRepository`
**表**：t_user、t_item、t_admin、t_report

### 接口清单

| 方法 | 路径 | 入参 | 返回 data | 说明 |
|---|---|---|---|---|
| GET | /api/admin/stats | — | Map{userCount,itemCount,adminCount,pendingReportCount} | 运营数据概览 |
| GET | /api/admin/users | — | List\<User\> | 全部用户（管理端视角） |
| PUT | /api/admin/users/{id}/status | 路径 id + ?status= | User | 启用/禁用用户 |
| GET | /api/admin/items | — | List\<Item\> | 全部商品（管理端视角） |
| PUT | /api/admin/items/{id}/off | 路径 id | Item | 下架商品（status→2） |

### 实现逻辑

- **统计**：分别 `count()` 用户/商品/管理员数，`findByStatus(0).size()` 统计待处理举报数，汇总为 Map —— 一张接口给管理首页仪表盘。
- **用户状态**：`findById` → set status（0 禁用 / 1 启用）→ save；被禁用用户登录接口会拦截（见模块一）。
- **商品下架**：`findById` → set `status=2` → save；下架后商品不在新端列表命中（前端配合过滤；/api/items 全量接口含所有状态，管理端可见）。

## 15. 接口调用链总览

```
浏览器 / 小程序 / Apifox / Swagger UI
        │  HTTP 请求（JSON，经 CorsConfig 跨域放行）
        ▼
   Controller（@RestController，/api/**）
        │  1) 解析入参（@PathVariable/@RequestParam/@RequestBody + DTO）
        │  2) 业务规则（唯一性校验 / MD5 / 状态流转 / 局部更新）
        │  3) 统一包装 Result.ok / Result.error
        ▼
   Repository（Spring Data JPA）
        │  派生方法 findByXxx / existsByXxx / deleteByXxx + @Query 游标查询
        ▼
   MySQL 8 张表（JPA 实体映射，ddl-auto=none，时间戳由 @PrePersist/@PreUpdate 维护）
```

**典型业务链路示例**

| 业务 | 链路 |
|---|---|
| 注册 | `POST /api/auth/register` → 查重 → MD5 → `UserRepository.save` → t_user |
| 登录 | `POST /api/auth/login` → MD5 → 比对 t_user / t_admin → 返回身份 |
| 发布+检索 | `POST /api/items` → t_item → `GET /api/items/page` 游标翻页检索 |
| 评价闭环 | 交易后 `POST /api/reviews` → 卖家 `PUT /api/reviews/{id}/reply` |
| 收藏去重 | `POST /api/favorites` 联合主键 + exists 校验 → `DELETE .../{userId}/{itemId}` 取消 |
| 举报治理 | 买家 `POST /api/reports`(status=0) → 管理端 `GET /api/reports?status=0` → `PUT .../handle`(1/2) |
| 违规处置 | 管理端 `PUT /api/admin/users/{id}/status` 禁号 → 该用户登录被拒 |
| 导出报表 | `GET /api/items/export` → CSV(UTF-8 BOM) 下载 |
